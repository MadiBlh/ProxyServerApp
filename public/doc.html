Proxy Server Log Tool — Code Documentation

A local Node.js reverse proxy that intercepts every HTTP and SOAP call between a front-end and its backend APIs, captures full request/response headers and bodies to disk, streams them live to an integrated inspection dashboard (Monaco editors), and lets you replay any captured request with custom overrides.

Node.js + Express 4 http-proxy 1.18 Zero DB — file based Vanilla JS dashboard Main proxy :4000 Redirect proxies :4001+

01 Bird's-Eye View

The problem it solves

When developing a web front-end against multiple backend microservices (REST or SOAP), you constantly need to answer: what exactly was sent, what came back, how long did it take? This tool sits on localhost:4000. You point your Vite dev-server proxy (or browser) at it; it forwards traffic to the right backend while keeping a permanent, browsable record of every exchange.

One process, several faces

A single Express server exposes multiple surfaces on the same port:

1. Reverse Proxy (default)

Every unmatched path falls through to proxyEngine.proxyMiddleware, which picks an app + backend by path prefix and relays the call (server.js:45).

2. Admin REST API

/dashboard-api/* manages applications, storage paths, logs, export, replay, redirect proxies and a Server-Sent-Events stream (src/routes/api.js).

3. Static Dashboard SPA

/dashboard serves public/index.html; assets under /dashboard-static/*; docs at /doc.

4. Redirect Proxy Servers

Each configured external forwarding target gets its own dedicated proxy server on an auto-assigned port (:4001+) (redirectProxyManager.js).

Key capabilities

  • Prefix-based routing: each configured backend declares a pathPrefix; the longest matching prefix wins (proxyEngine.js:214).
  • Capture to disk: bodies in logs/, metadata in headers/, all keyed by one UUID per transaction.
  • Live feed: new captures are pushed instantly to open dashboards via SSE — including captures from redirect proxies.
  • Inspect: Monaco editor panes auto-detect JSON/XML and pretty-print; cookie headers get special treatment.
  • Replay: re-fire any captured call with edited URL/method/headers/body (replayService.js:3).
  • Export: save a request/response pair straight into the user's Downloads folder.
  • Redirect proxies: apps can declare external API forwarding rules (e.g. payment gateway) that run on dedicated ports, still fully captured and streamed.
  • Configurable storage: where config/, logs/ and headers/ live can be changed via env vars, settings.json or the dashboard.
Mental model: think "Charles Proxy / Fiddler, but self-hosted in Node, configured by a JSON file, with a web UI instead of a desktop app."

05 Proxied Request Lifecycle (end to end)

  1. A client hits any path on port 4000. Express middleware chain runs: CORS → admin API → static → dashboard/doc → root redirect; everything else reaches proxyMiddleware (server.js:45).
  2. The middleware buffers the entire raw request body in memory, stashing req._proxyRawBodyStr and req._proxyRawBuffer (proxyEngine.js:149-156).
  3. It resolves the effective path, optionally stripping an explicit /proxy/:appId prefix (proxyEngine.js:159-168), then loads config and keeps only active apps (proxyEngine.js:170-171).
  4. Target selection cascade:
    • a) explicit app id from route param, x-proxy-app-id/x-app-id header or _appId query (proxyEngine.js:183);
    • b) global scan of every active backend across all active apps, matched by longest pathPrefix first; backends with no prefix act as catch-alls. Redirections are excluded here — they have their own ports (proxyEngine.js:197-223);
    • c) fallback: match app whose frontEndUrl appears in Referer/Origin, use its first backend (proxyEngine.js:229-241);
    • d) still nothing → 404 listing the configured prefixes (proxyEngine.js:244-250).
  5. Request is stamped with correlation state: _proxyRequestId (UUID), _proxyStartTime, _proxyApp, _proxyBackendService, _proxyTargetUrl (proxyEngine.js:254-258).
  6. The buffered body is wrapped in a PassThrough stream (it was already consumed) and handed to proxy.web(req, res, { target, buffer }) (proxyEngine.js:260-268).
  7. Upstream responds. Because selfHandleResponse: true (proxyEngine.js:10), the proxyRes handler collects chunks, computes duration, and calls logManager.saveLogEntry which writes four files (proxyEngine.js:53-79, details in section 14).
  8. A compact summary is broadcast to every SSE subscriber (proxyEngine.js:82-94).
  9. Status code plus upstream headers are copied to the client — except content-length / transfer-encoding — and the buffered body is flushed with res.end(buffer) (proxyEngine.js:96-109).
  10. The dashboard's EventSource receives the summary, filters by the currently selected app, and prepends it to the list (app.js:289-307). Clicking a row fetches /dashboard-api/logs/:id and renders bodies into the Monaco panes.
  11. If upstream is unreachable, the error handler records a FAILED capture with status 502 and answers the client with a JSON error (proxyEngine.js:113-142).

Redirect proxy lifecycle

A request to a redirect port (http://localhost:4001, etc.) never touches proxyMiddleware. The subscriber app is resolved from the x-proxy-app-id/x-app-id header, the Referer/Origin, or the first subscriber of that shared port (redirectProxyManager.js:37-65), then the request flows through the same buffer → log → broadcast → forward pipeline of that port's own http-proxy instance (redirectProxyManager.js:94-147).

06 Admin API & SSE Feed

Design notes

  • router.use(express.json()) parses bodies only for these administrative endpoints (api.js:11) — proxied traffic never goes through here because the proxy middleware consumes it first.
  • All CRUD delegates to configManager / settingsManager; validation errors surface as HTTP 400, missing resources as 404.
  • Every application create/update/delete re-runs redirectProxyManager so redirect servers mirror the stored config immediately (api.js:53).
  • The trailing catch-all inside the router just calls next() (api.js:163-165): unknown paths such as /api/users intentionally fall out of /dashboard-api and continue toward the proxy.

Settings API

  • GET /dashboard-api/settings returns the effective paths plus flags (isDefaultConfig, isDefaultLogs) and the defaults (api.js:16-22).
  • PUT /dashboard-api/settings accepts configDir, logsDir and migrateExistingConfig; it persists to settings.json, optionally copies applications.json, and re-syncs redirect proxies (api.js:25-39).

SSE channel mechanics

  • GET /dashboard-api/events sets the three canonical SSE headers and registers the res object in sseClients[] (api.js:150-160, proxyEngine.js:22-24).
  • On socket close the client is removed (proxyEngine.js:26-29), preventing leaks.
  • broadcastLogEvent writes data: {JSON}\n\n to each subscriber, swallowing per-client write errors (proxyEngine.js:31-40).
  • server.js:74 hands the same sseClients array to redirectProxyManager, so redirect-port captures appear in the same unified live feed.

Replay semantics

The endpoint accepts optional overrides (customUrl/customMethod/customHeaders/customBody); anything omitted is taken from the stored capture. System headers that break outbound fetches (host, content-length, connection, accept-encoding) are stripped before sending (replayService.js:16-20).

08 Data Model & Storage

config/applications.json

Written by configManager.saveApplications with 2-space indentation. Shape (see defaults at configManager.js:106-135):

application entry
{
  "id": "app-default-1",                       // stable id (uuidv4 unless provided)
  "name": "Sample JSON Store API",
  "frontEndUrl": "http://localhost:3000",      // used by the Referer fallback matcher
  "backendUrls": [                             // internal backends relayed through :4000
    { "id": "be-1", "name": "JSON Placeholder API",
      "url": "https://jsonplaceholder.typicode.com", "pathPrefix": "/posts" }
  ],
  "redirectUrls": [                            // external forwarding rules (optional)
    { "id": "red-1", "name": "Payment Gateway",
      "targetUrl": "https://api.example.com", "port": 4001 }  // port auto-assigned
  ],
  "isActive": true                             // inactive apps are skipped by routing
}

backendUrls are relayed by the main proxy on port 4000 and matched by pathPrefix. redirectUrls do not declare a prefix — each receives a dedicated proxy server on an auto-assigned port (see section 13 & 16). Multiple apps pointing at the same targetUrl share one port.

settings.json (optional)

When the user customizes storage through the dashboard or PUT /settings, settingsManager persists { configDir, logsDir } to settings.json in the project root (empty strings = project defaults). Resolution order everywhere is: environment variable → settings.json → project default (settingsManager.js:51-63).

Extension sniffing

logManager.getFileExtension decides between json/xml/html/js/css/txt using the Content-Type substring, falling back to a first-character sniff of the body ({ or [ → json, < → xml) (logManager.js:19-37). The chosen extension drives both the stored filename and the Monaco language on the client.

Exports

09 server.js — Entry Point

Orders all of the app.use mounts; specific mounts must precede the catch-all proxy.

  • L1: requires bootstrap.js first, so the util._extend polyfill exists before http-proxy loads.
  • L3-9: requires express, cors, the admin router, proxy middleware, and both service managers.
  • L11-12: app instance; PORT = process.env.PORT || 4000.
  • L15: global CORS. L18: admin API mount. L21: static mount. L24-31: dashboard SPA + doc page. L34-40: conditional root redirect.
  • L45: app.use(proxyMiddleware) — the default face of the server.
  • L50-71: loads configManager.getApplications() (which seeds config/applications.json with sample apps on first boot) and migrates legacy redirect entries that lack a port, assigning one via configManager.assignRedirectPort.
  • L74-77: shares the SSE client array with redirectProxyManager and starts one proxy server per active redirect URL.
  • L79-93: listens on 0.0.0.0 so LAN devices can use the proxy; prints a startup banner including the redirect proxy list.
server.js:45

The catch-all mount

// 5. Proxy Server Entrypoint: http://localhost:4000
//    ALL requests (e.g. Vite target: 'http://localhost:4000' forwarding /api/users, /api/todos, etc.)

Because this is mounted last, dashboard/admin/static/doc routes always win. Everything unmatched becomes proxied traffic — that is what makes the tool transparent for front-end development.

10 src/utils/bootstrap.js — Polyfill Guard

http-proxy internally uses the legacy util._extend, which emits the DEP0060 deprecation warning on modern Node. This 18-line module redefines it as a thin Object.assign wrapper before http-proxy is required.

bootstrap.js:8-16

Monkey-patching util._extend

if (util) {
  Object.defineProperty(util, '_extend', {
    value: function (target, source) {
      return Object.assign(target || {}, source || {});
    },
    writable: true,
    configurable: true
  });
}

defineProperty is required because util._extend is non-writable by assignment; configurable: true keeps the patch reversible. Both arguments are null-guarded, mirroring legacy semantics.

Both server.js:1 and proxyEngine.js:1 require it defensively, whichever loads first.

11 src/utils/uuid.js — ID Generator

Zero-dependency RFC-4122 v4 generator. It walks the template string xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx, replacing each x with a random hex nibble and each y with a variant-constrained nibble. generateUuid.v4 = generateUuid mimics the popular uuid package API so call sites read naturally.

uuid.js:7-11

The nibble math

return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, function (c) {
  const r = (Math.random() * 16) | 0;
  const v = c === 'x' ? r : (r & 0x3) | 0x8;
  return v.toString(16);
});

(Math.random() * 16) | 0 yields 0..15. For the variant slot, (r & 0x3) | 0x8 restricts the two high bits per RFC-4122, producing one of 8/9/a/b. The literal 4 in the template fixes the version field.

Used for: application/backend ids (configManager.js:167), per-request capture ids (proxyEngine.js:254) and error-path fallback ids (proxyEngine.js:117).

15 src/services/proxyEngine.js — Proxy Core

The heart of the app (277 lines): a configured http-proxy instance, an SSE fan-out list, two event handlers, and the routing middleware for the main port.

Proxy instance options

proxyEngine.js:9-17
const proxy = httpProxy.createProxyServer({
  selfHandleResponse: true,      // we buffer + log the response ourselves
  changeOrigin: true,            // rewrite Host header to the target
  secure: false,                 // accept self-signed upstream certs
  cookieDomainRewrite: { '*': '' }  // scope cookies to localhost (see below)
});

cookieDomainRewrite: { '*': '' } removes the Domain attribute from every Set-Cookie, so cookies set by proxied backends remain valid on localhost. A string '*' would emit Domain=* which browsers reject, hence the object form.

Response interception ('proxyRes')

  • Chunks accumulate in an array; nothing is forwarded until end (proxyEngine.js:55-59).
  • Duration uses the timestamp stashed by the middleware — i.e. includes body buffering time, not just upstream time (proxyEngine.js:44-45).
  • After logging + broadcasting, upstream headers are copied but hop-by-hop/length headers are skipped since our re-emitted body may differ (proxyEngine.js:98-103).
  • res.end(responseBuffer) finally releases the response to the caller (proxyEngine.js:109).

Error handling ('error')

Logs a FAILED capture with synthetic 502 status and the error text as body, then replies 502 {error, details} if headers were not already sent (proxyEngine.js:113-142). A fresh UUID is generated if the failure happened before stamping (proxyEngine.js:117).

Target selection (middleware)

Full cascade documented in section 5. The decisive trick is longest-prefix-wins:

proxyEngine.js:214-221

Most-specific prefix wins

// Sort all active routes by pathPrefix length descending (longest/most specific prefix first).
allActiveRoutes.sort((a, b) => (b.pathPrefix || '').length - (a.pathPrefix || '').length);

// Find the first prefix that matches the request path (missing prefix = catch-all '/')
const match = allActiveRoutes.find(be => {
  const prefix = (be.pathPrefix || '/').trim() || '/';
  return requestPath.startsWith(prefix);
});

Sorting once and taking the first startsWith hit means /external/payment/refund correctly lands on a /external/payment rule rather than a bare /external backend. Backends with an empty prefix sort last and act as catch-alls for any path.

proxyEngine.js:260-268

Restreaming the consumed body

// Re-stream buffered body for http-proxy
const Stream = require('stream');
const bufferStream = new Stream.PassThrough();
bufferStream.end(rawReqBuffer);

proxy.web(req, res, {
  target: targetBackendUrl,
  buffer: bufferStream
});

We already drained the request stream to capture the body, so http-proxy would see an empty stream. Feeding a PassThrough pre-filled with the saved buffer restores the payload without re-reading the socket.

Redirections are not matched here — the middleware only indexes backendUrls (see the comment at proxyEngine.js:208-209). Redirect traffic is the responsibility of redirectProxyManager.js (section 16).

16 src/services/redirectProxyManager.js — Redirect Proxies

Runs dedicated HTTP proxy servers on separate ports for every configured redirectUrl. If two applications declare the same external targetUrl, they share one server/port — the port bookkeeping in configManager.assignRedirectPort guarantees no collision.

State

runningProxies is a Map(port -> { server, proxy, targetUrl, subscribers[] }) (redirectProxyManager.js:17-18) where subscribers grows as more apps reuse the same port. The shared sseClients array is injected from the main engine so redirect captures appear in the same dashboard feed (redirectProxyManager.js:23-25).

Subscriber resolution
