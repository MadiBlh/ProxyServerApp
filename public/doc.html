Proxy Server Log Tool — Code Documentation

A local Node.js reverse proxy that intercepts every HTTP and SOAP call between a front-end and its backend APIs, captures full request/response headers and bodies to disk, streams them live to an integrated inspection dashboard (Monaco editors), and lets you replay any captured request with custom overrides.

Node.js + Express 4 http-proxy 1.18 Zero DB — file based Vanilla JS dashboard Port 4000

01 Bird's-Eye View

The problem it solves

When developing a web front-end against multiple backend microservices (REST or SOAP), you constantly need to answer: what exactly was sent, what came back, how long did it take? This tool sits on localhost:4000. You point your Vite dev-server proxy (or browser) at it; it forwards traffic to the right backend while keeping a permanent, browsable record of every exchange.

One process, three faces

A single Express server exposes three distinct surfaces on the same port:

1. Reverse Proxy (default)

Every unmatched path falls through to proxyEngine.proxyMiddleware, which picks an app + backend by path prefix and relays the call (server.js:39).

2. Admin REST API

/dashboard-api/* manages applications, logs, export, replay and a Server-Sent-Events stream (src/routes/api.js).

3. Static Dashboard SPA

/dashboard serves public/index.html; assets under /dashboard-static/*; docs at /doc.

Key capabilities

  • Prefix-based routing: each configured backend declares a pathPrefix; the longest matching prefix wins (proxyEngine.js:215).
  • Capture to disk: bodies in logs/, metadata in headers/, all keyed by one UUID per transaction.
  • Live feed: new captures are pushed instantly to open dashboards via SSE.
  • Inspect: Monaco editor panes auto-detect JSON/XML and pretty-print; cookie headers get special treatment.
  • Replay: re-fire any captured call with edited URL/method/headers/body (replayService.js).
  • Export: save a request/response pair straight into the user's Downloads folder.
  • Redirections: apps can declare external API forwarding rules (e.g. payment gateway) alongside normal backends.
Mental model: think "Charles Proxy / Fiddler, but self-hosted in Node, configured by a JSON file, with a web UI instead of a desktop app."

05 Proxied Request Lifecycle (end to end)

  1. A client hits any path on port 4000. Express middleware chain runs: CORS → admin API → static → dashboard/doc → root redirect; everything else reaches proxyMiddleware (server.js:39).
  2. The middleware buffers the entire raw request body in memory, stashing req._proxyRawBodyStr and req._proxyRawBuffer (proxyEngine.js:147-154).
  3. It resolves the effective path, optionally stripping an explicit /proxy/:appId prefix (proxyEngine.js:157-166), then loads config and keeps only active apps (proxyEngine.js:168-169).
  4. Target selection cascade:
    • a) explicit app id from route param, x-proxy-app-id/x-app-id header or _appId query (proxyEngine.js:181);
    • b) global scan of every active backend + redirection across all apps, matched by longest pathPrefix first (proxyEngine.js:195-223);
    • c) fallback: match app whose frontEndUrl appears in Referer/Origin, use its first backend (proxyEngine.js:226-239);
    • d) still nothing → 404 listing the configured prefixes (proxyEngine.js:241-247).
  5. Request is stamped with correlation state: _proxyRequestId (UUID), _proxyStartTime, _proxyApp, _proxyBackendService, _proxyTargetUrl (proxyEngine.js:251-255).
  6. The buffered body is wrapped in a PassThrough stream (it was already consumed) and handed to proxy.web(req, res, { target, buffer }) (proxyEngine.js:258-265).
  7. Upstream responds. Because selfHandleResponse: true (proxyEngine.js:10), the proxyRes handler collects chunks, computes duration, and calls logManager.saveLogEntry which writes four files (proxyEngine.js:57-77, details in section 13).
  8. A compact summary is broadcast to every SSE subscriber (proxyEngine.js:80-92).
  9. Status code plus upstream headers are copied to the client — except content-length / transfer-encoding — and the buffered body is flushed with res.end(buffer) (proxyEngine.js:94-108).
  10. The dashboard's EventSource receives the summary, filters by the currently selected app, and prepends it to the list (app.js:287-297). Clicking a row fetches /dashboard-api/logs/:id and renders bodies into the Monaco panes.
  11. If upstream is unreachable, the error handler records a FAILED capture with status 502 and answers the client with a JSON error (proxyEngine.js:111-140).

06 Admin API & SSE Feed

Design notes

  • router.use(express.json()) parses bodies only for these administrative endpoints (api.js:9) — proxied traffic never goes through here because the proxy middleware consumes it first.
  • All CRUD delegates to configManager; validation errors surface as HTTP 400, missing resources as 404.
  • The trailing catch-all inside the router just calls next() (api.js:119-121): unknown paths such as /api/users intentionally fall out of /dashboard-api and continue toward the proxy.

SSE channel mechanics

  • GET /dashboard-api/events sets the three canonical SSE headers and registers the res object in sseClients[] (api.js:106-116, proxyEngine.js:20-22).
  • On socket close the client is removed (proxyEngine.js:24-27), preventing leaks.
  • broadcastLogEvent writes data: {JSON}\n\n to each subscriber, swallowing per-client write errors (proxyEngine.js:29-38).

Replay semantics

The endpoint accepts optional overrides (customUrl/customMethod/customHeaders/customBody); anything omitted is taken from the stored capture. System headers that break outbound fetches (host, content-length, connection, accept-encoding) are stripped before sending (replayService.js:16-20).

Extension sniffing

logManager.getFileExtension decides between json/xml/html/js/css/txt using the Content-Type substring, falling back to a first-character sniff of the body ({ or [ → json, < → xml) (logManager.js:17-35). The chosen extension drives both the stored filename and the Monaco language on the client.

Exports

Export sanitizes the user-supplied prefix with [^a-zA-Z0-9_-] → _ (logManager.js:203) and writes two files into os.homedir()/Downloads (logManager.js:189-195).

09 server.js — Entry Point

Fifty lines that wire everything together. Order of app.use calls is critical: specific mounts must precede the catch-all proxy.

  • L1: requires bootstrap.js first, so the util._extend polyfill exists before http-proxy loads.

  • L14: global CORS. L17: admin API mount. L20: static mount. L23-25: dashboard SPA. L28-34: conditional root redirect.
  • L39: app.use(proxyMiddleware) — the default face of the server.
  • L42: configManager.getApplications() eagerly seeds config/applications.json with sample apps on first boot.
  • L44-50: listens on 0.0.0.0 so LAN devices can use the proxy; prints startup banner.
server.js:36-39

The catch-all mount

// 5. Proxy Server Entrypoint: http://localhost:4000
//    ALL requests (e.g. Vite target: 'http://localhost:4000' forwarding /api/users, /api/todos, etc.)
//    pass through proxyMiddleware to the configured backend microservices.
app.use(proxyMiddleware);

Because this is mounted last, dashboard/admin/static/doc routes always win. Everything unmatched becomes proxied traffic — that is what makes the tool transparent for front-end development.

10 src/utils/bootstrap.js — Polyfill Guard

http-proxy internally uses the legacy util._extend, which emits the DEP0060 deprecation warning on modern Node. This 18-line module redefines it as a thin Object.assign wrapper before http-proxy is required.

bootstrap.js:8-16

Monkey-patching util._extend

if (util) {
  Object.defineProperty(util, '_extend', {
    value: function (target, source) {
      return Object.assign(target || {}, source || {});
    },
    writable: true,
    configurable: true
  });
}

defineProperty is required because util._extend is non-writable by assignment; configurable: true keeps the patch reversible. Both arguments are null-guarded, mirroring legacy semantics.

Both server.js:1 and proxyEngine.js:1 require it defensively, whichever loads first.

11 src/utils/uuid.js — ID Generator

Zero-dependency RFC-4122 v4 generator. It walks the template string xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx, replacing each x with a random hex nibble and each y with a variant-constrained nibble. generateUuid.v4 = generateUuid mimics the popular uuid package API so call sites read naturally.

uuid.js:7-11

The nibble math

return 'xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx'.replace(/[xy]/g, function (c) {
  const r = (Math.random() * 16) | 0;
  const v = c === 'x' ? r : (r & 0x3) | 0x8;
  return v.toString(16);
});

(Math.random() * 16) | 0 yields 0..15. For the variant slot, (r & 0x3) | 0x8 restricts the two high bits per RFC-4122, producing one of 8/9/a/b. The literal 4 in the template fixes the version field.

Used for: application/backend ids (configManager.js:91), per-request capture ids (proxyEngine.js:251) and error-path fallback ids (proxyEngine.js:115).

14 src/services/proxyEngine.js — Proxy Core

The heart of the app (~273 lines): a configured http-proxy instance, an SSE fan-out list, two event handlers, and the routing middleware.

Proxy instance options

proxyEngine.js:9-15
const proxy = httpProxy.createProxyServer({
  selfHandleResponse: true,   // we buffer + log the response ourselves
  changeOrigin: true,         // rewrite Host header to the target
  secure: false,              // accept self-signed upstream certs
  cookieDomainRewrite: '*',   // keep cookies working behind localhost
  cookiePathRewrite: '*'
});

Response interception ('proxyRes')

  • Chunks accumulate in an array; nothing is forwarded until end (proxyEngine.js:53-57).
  • Duration uses the timestamp stashed by the middleware — i.e. includes body buffering time, not just upstream time (proxyEngine.js:42-43).
  • After logging + broadcasting, upstream headers are copied but hop-by-hop/length headers are skipped since our re-emitted body may differ (proxyEngine.js:96-100).
  • res.end(responseBuffer) finally releases the response to the caller (proxyEngine.js:107).

Error handling ('error')

Logs a FAILED capture with synthetic 502 status and the error text as body, then replies 502 {error, details} if headers were not already sent (proxyEngine.js:111-140). A fresh UUID is generated if the failure happened before stamping (proxyEngine.js:115).

Target selection (middleware)

Full cascade documented in section 5. The decisive trick is longest-prefix-wins:

proxyEngine.js:215-218

Most-specific prefix wins

// Sort all active routes by pathPrefix length descending (longest/most specific prefix first)
allActiveRoutes.sort((a, b) => (b.pathPrefix || '').length - (a.pathPrefix || '').length);

// Find matching backend/redirect service by pathPrefix
const match = allActiveRoutes.find(be => requestPath.startsWith(be.pathPrefix.trim()));

Sorting once and taking the first startsWith hit means /external/payment/refund correctly lands on a /external/payment rule rather than a bare /external backend.

proxyEngine.js:257-265

Restreaming the consumed body

// Re-stream buffered body for http-proxy
const Stream = require('stream');
const bufferStream = new Stream.PassThrough();
bufferStream.end(rawReqBuffer);

proxy.web(req, res, {
  target: targetBackendUrl,
  buffer: bufferStream
});

We already drained the request stream to capture the body, so http-proxy would see an empty stream. Feeding a PassThrough pre-filled with the saved buffer restores the payload without re-reading the socket.

15 src/services/replayService.js — Replay Engine

One exported async function. Resolution order per field: explicit override → stored capture → sensible default (method POST). The URL combines reqMeta.targetUrl + reqMeta.endpoint when rebuilt from history (replayService.js:6).

replayService.js:15-20

Header hygiene before fetch()

// Clean up system headers that cause fetch errors
const cleanHeaders = { ...headers };
delete cleanHeaders['host'];
delete cleanHeaders['content-length'];
delete cleanHeaders['connection'];
delete cleanHeaders['accept-encoding'];

These four are either forbidden or auto-managed by fetch/undici; leaving them in causes immediate TypeErrors or corrupted framing. Body attachment happens only for methods that allow one (replayService.js:29-31). Failures never throw to the caller — they return a structured {success:false,...} object (replayService.js:52-62).

Negotiating "browser navigation" vs proxied API call on the same URL

const accept = req.headers['accept'] || '';

Hitting http://localhost:4000 in a tab shows the dashboard; the exact same URL used as a Vite proxy target forwards traffic. The Accept header plus absence of explicit proxy markers is the discriminator.

The switch that makes logging possible

selfHandleResponse: true,

Tells http-proxy not to pipe the upstream response automatically. Instead our 'proxyRes' handler receives it whole, buffers it, persists it, and only then answers the client. Without this option the tool could observe but not record.

proxyEngine.js:97-99

Dropping framing headers before re-emitting

if (lowerKey === 'content-length' || lowerKey === 'transfer-encoding') {
  return;
}

The buffered body is re-sent verbatim today, but nothing guarantees byte-equality after future transforms (e.g. decompression). Stale length/chunked headers would corrupt the reply, so they are deliberately skipped and Node recomputes them.

Route param wins, then two dedicated headers, then a query flag — covering CLI tools (query), browsers (header) and direct /proxy/:appId/... links alike.
